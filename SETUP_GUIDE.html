الخطوة 1 — إنشاء مشروع Firebase
1

سجل دخول بحساب Google واضغط "Add project"

2

اسم المشروع

3

أضف Web App

4

انسخ الـ Config

كيف يشتغل نظام الدخول والصلاحيات

النظام ده شغال بالكامل في الكود — مش محتاج تضيف أي حاجة، بس لازم تفهم إزاي يشتغل عشان تضبط البيانات صح.

شاشة الدخول — إيه اللي بيحصل؟
المحاسب
  1. بيختار المدرسة من الـ grid
  2. بيكتب الإيميل والباسورد
  3. النظام بيتحقق إن الإيميل ده موجود في قائمة users للمدرسة المختارة
  4. لو مش موجود → رفض تلقائي
  5. لو موجود → دخول على dashboard المدرسة دي بس
الأدمن
  1. بيضغط "الدخول كأدمن" في أسفل الصفحة
  2. بيكتب الإيميل والباسورد
  3. النظام بيتحقق إن الإيميل موجود في مصفوفة ADMINS
  4. لو موجود → دخول على admin.html مباشرة
  5. يقدر يشوف ويتنقل بين كل المدارس
كيف النظام بيمنع المحاسب من دخول مدرسة غلط؟

الكود ده موجود في index.html ويتنفذ تلقائياً عند كل محاولة دخول:

// بعد ما Firebase يتحقق من الإيميل والباسورد... // هل الإيميل ده في قائمة users للمدرسة المختارة؟ if (!selectedSchool.users.includes(email)) { showAlert('هذا الحساب غير مصرح له بالدخول على هذه المدرسة'); auth.signOut(); ← بيعمل logout فوراً من Firebase return; } // لو عدى الـ check → يحفظ الـ session ويروح للـ dashboard SESSION.set({ schoolId: selectedSchool.id, role: 'accountant', ... });
مثال عملي: لو محاسب مدرسة 1 حاول يختار مدرسة 2 ويدخل بنفس إيميله — النظام هيرفضه حتى لو الباسورد صح، لأن إيميله مش في قائمة users بتاعة مدرسة 2.
الأدمن — إيه اللي يقدر يعمله؟
ملخص كل المدارس
إجمالي الشهر + عدد العمليات لكل مدرسة
كل التحصيلات
يشوف ويفلتر تحصيلات كل المدارس مع بعض
تبديل المدرسة
يدخل على أي مدرسة ويشوف الـ dashboard بتاعتها
تصدير Excel
يصدر بيانات كل المدارس أو مدرسة محددة
ملاحظة مهمة: الصلاحيات دي بتتحكم فيها مصفوفة users في firebase-config.js — مش في Firebase نفسه. يعني لو حبيت تضيف أو تشيل محاسب، بتعدل الملف ده بس.

الخطوة 4 — إعداد Firestore Database
1

إنشاء قاعدة البيانات

من Firebase Console: Firestore Database → Create database → Start in production mode → اختر region قريبة (europe-west1 أو me-central1)

2

إعداد الـ Security Rules

من Firestore → Rules، انسخ والصق الكود ده:

rules_version = '2'; service cloud.firestore { match /databases/{database}/documents { // فقط المستخدمين المسجلين يقدرون يقرأوا ويكتبوا match /transactions/{docId} { allow read, write: if request.auth != null; } // باقي المجموعات محمية match /{document=**} { allow read, write: if request.auth != null; } } }
الـ rules دي بتسمح لأي مستخدم logged in يعمل read/write. الصلاحيات التفصيلية (مين يشوف مدرسة مين) بتتعمل في الـ JavaScript مش في Firebase Rules.
3

الـ Indexes المطلوبة مهم جداً

لازم تعمل Composite Indexes عشان الـ queries تشتغل. من Firestore → Indexes → Composite → Add index:

transactions schoolId (Asc) + date (Asc) + createdAt (Desc) مطلوب
transactions schoolId (Asc) + date (Desc) مطلوب
transactions schoolId (Asc) + createdAt (Desc) مطلوب
transactions schoolId (Asc) + stage (Asc) + date (Asc) مطلوب
transactions schoolId (Asc) + paymentItem (Asc) + date (Asc) مطلوب
أسهل طريقة: شغّل النظام وافتح الـ Console في المتصفح (F12). أي query محتاجة index هيظهر في الـ console رسالة خطأ فيها رابط مباشر تضغط عليه وهو هيعمل الـ index تلقائياً!

الخطوة 6 — تشغيل ونشر النظام
A

تشغيل محلياً (للتجربة)

مش ممكن تفتح الملفات مباشرة double-click — محتاج web server بسيط:

# لو عندك Python: python -m http.server 8080 # لو عندك Node.js: npx serve . # أو حمّل VS Code + Live Server extension

ثم افتح المتصفح على: http://localhost:8080

B

نشر على Firebase Hosting (مجاني ومريح)

# تثبيت Firebase CLI npm install -g firebase-tools # تسجيل دخول firebase login # في مجلد المشروع firebase init hosting # الإجابة على الأسئلة: # Which Firebase project? → اختر مشروعك # Public directory? → . (نقطة) # Single-page app? → No # Overwrite index.html? → No # رفع الملفات firebase deploy

هيديك رابط زي: https://school-accounting.web.app

C

أي hosting تاني

ارفع كل الملفات على أي hosting عادي (cPanel, Netlify, Vercel). المشروع static files بس.

لازم تضيف الـ domain بتاعك في Firebase Console تحت Authentication → Settings → Authorized domains عشان الـ login يشتغل.
